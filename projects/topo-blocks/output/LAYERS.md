# topo-blocks — layer documentation

**Map**: None — this project produces print/apparel art (PNG images), not layers for an ArcGIS Pro map. No `.gpkg` or georeferenced raster is written.
**Script**: `main.py` (commit `8a47705` "Add topo-blocks design creator (#2)", 2025-10-02)
**Overview**: Turns an elevation-contour shapefile into a three-panel "block" design: three colored rectangles spanning the contour extent, with the contour lines buffered and subtracted from each rectangle as cutouts, and the mountain name rendered below in white serif text. A batch mode renders one PNG per built-in color scheme (16 schemes, grouped as monochrome, muted earth, tetradic complementary, and single-color gradients — README says they were chosen for t-shirt/screen printing). Output paths are supplied on the command line (`--output` / `--batch-output`), so this `output/` directory holds no generated files by default.

## {Mountain_Name}_{scheme}.png *(declared by the script, not present locally)*
- **Role**: Final deliverable — a stylized three-block topographic design of one mountain in one color scheme, intended for printing (README: "optimized for t-shirt printing and fabric") rather than for use as a map layer.
- **Source**: A user-supplied contour shapefile (LineString/MultiLineString elevation contours; README suggests USGS National Map downloads, OSM extracts, or `gdal_contour` from a DEM at 10–50 m intervals), plus an optional border shapefile that, when present, sets the design extent (`TopoBlockDesigner.__init__` uses `border.total_bounds`, else `contours.total_bounds`). No input data is bundled with the project.
- **Processing**: `TopoBlockDesigner.create_block_design` in `main.py` — the contour extent is split into three equal-width rectangles with `gap_percent=0.005` gaps; contours intersecting each rectangle are found via a spatial index, clipped, buffered by `line_width * (width / 500)` (default `line_width=0.8`, so buffer scales with extent), unioned, and subtracted from the rectangle (`box.difference`); the remaining geometry is plotted in that block's color with matplotlib and saved via `plt.savefig` at `dpi=300`, `figsize=(12, 12)`, transparent background by default, `bbox_inches='tight'`. If `show_text` (default on), the mountain name is drawn below the blocks, right-aligned at the right block edge, white serif, adaptively sized (12–48 pt). `batch_create_designs` loops this over the 16 color-scheme dicts, naming files `{safe_mountain_name}_{scheme_name}{name_suffix}.png` (spaces and `/` in the name replaced with `_`); `batch_process_mountains` additionally nests output per mountain-folder name.
- **Rationale** *(reconstructed)*: Cutouts are made by geometric difference (buffered lines subtracted from the block polygons) rather than by drawing lines on top, so with the default transparent background the contours read as true see-through cuts — consistent with the screen-printing intent stated in the README. The 16 color schemes and their grouping are documented in the README as print/fabric-friendly choices. CHANGES.md records the text feature as a later addition: the `mountain_name` parameter existed in the signature before it actually rendered, and the white-serif, right-aligned, close-below-the-blocks placement was a deliberate layout decision (bottom margin reduced to `height * 0.06`). Why exactly three blocks, or the specific buffer scale of `width / 500`, is unknown.
