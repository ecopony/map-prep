# sky-islands — layer documentation

**Map**: Sky Islands — the Madrean Archipelago (brief: `mapmaking/projects/sky-islands/brief.md`; ArcGIS Pro project: SkyIslands, not yet created)
**Script**: `main.py` + `transect.py` (biome-stack panel, 2026-09-19) (branch `hundredth-meridian`, first run 2026-08-20, frame enlarged and chart-styling layers added 2026-08-27, isobaths replaced by sea_depth.tif, land collapsed to islands / other_land, frame enlarged again 2026-08-28)
**Overview**: Renders the ~55 forested ranges between the Mogollon Rim and the Sierra Madre Occidental as a literal archipelago. No boundary file exists for the ranges, so the islands are *derived* — and the derivation is the map: threshold the DEM at Deyo's 1,600 m definitional elevation, drop the two "mainlands" (anything connected to the frame edge), attribute each remaining landmass with its woodland cover, and filter. `islands` is the foreground (hypsometric tint + `hillshade_islands*.tif` + `treecover_islands.tif` + `contours`, crisp shoreline); the sea is `sea_depth.tif` (continuous ramp) or `elevation_bands` (stepped), with `ocean` for the real Gulf of California — hillshade is masked to land so the two treatments never overlap; `elevation_bands` gives the reverse-bathymetry banding for the desert "sea" and the bands above the shoreline; `other_land` (mainlands + failed candidates ≥ 50 km²) is the one flat scenery layer, with matching `hillshade_other_land.tif` / `treecover_other_land.tif`; `islands_candidates` is the unfiltered set for tuning the area/woodland cutoffs in Pro. Processing runs on a custom equal-area Albers grid centered on the archipelago (`+proj=aea +lat_1=28.3 +lat_2=33.7 +lat_0=31 +lon_0=-110 +datum=WGS84`), chosen over EPSG:5070 because comparing island areas and gaps is the point and 5070's parallels distort this far south — set that as the **map** coordinate system in Pro (paste the proj string, or import it from `dem_cop90_aea.tif`), with **map rotation 56°** (decided 2026-08-27) so the chain runs horizontal, NW/Mogollon end slightly high. Rasters stay on the Albers grid; **all vector layers are written in EPSG:4326** and projected on the fly, per repo convention (*2026-08-20: the first run wrote vectors in the custom CRS and ArcGIS Pro refused them — a proj-string CRS has no authority code, so the GeoPackage SRS row is "unknown"*). Display frame: lon/lat (-123, 19, -98, 41.5) — grown a third time on 2026-08-28 after the user widened the layout for context (Nevada / Colorado to Nayarit / Zacatecas) and the rotated corners ran off the data at (-118.5, 22, -101.5, 39.5); before that grown twice on 2026-08-27 (from -113..-107/27..35, then -115.5..-104.5/25..36.5) because the 56°-rotated layout kept sweeping outside the data; final size applies the user's rule of thumb, *build background sources 1.5× bigger than the estimated need*. Both mainlands still run out of the frame (the mainland test depends on it); island membership is the separate archipelago box, so frame growth does not change the island set.

**Status / open items** (2026-08-28): derivation stable at 143 islands; first full layout exists (flat white `other_land`, tan islands with `hillshade_islands`, `sea_depth` ramp, 2° graticule, letterspaced physical names in a serif, states/cities in Kumbh Sans, title at the bottom, small North America locator inset). Open: (1) ~~`other_land` failed-candidate specks clutter the page~~ — resolved 2026-09-16 with the `min_display_km2 = 50` scenery floor (see `other_land`); (2) the real `ocean` needs a fill distinct from the `sea_depth` ramp so the metaphor stays legible; (3) ~~island `name` is still empty~~ — 39 islands named 2026-09-19 from `names.csv` (see `islands`); the Sonoran rows are placed by geography and carry a `confidence` flag worth checking in Pro; (4) woodland mask is EarthEnv as a stand-in for Brown & Lowe / NALCMS; (5) "Mogollon Rim" label not yet placed, and the Fenneman plural "Colorado Plateaus" should read "Colorado Plateau" on the map. Known caveat: at 1,600 m the Gila / Black Range country is continuous with the Mogollon block, so New Mexico ranges east of ~109°W are `other_land`, not islands — worth a margin note or a second shoreline.

## dem_cop90_aea.tif
- **Role**: Elevation basis for everything — the shoreline threshold, the tint bands, and the hillshade.
- **Source**: Copernicus GLO-90 DEM via the OpenTopography global DEM API (`OPEN_TOPOGRAPHY_API_KEY`; raw geographic tiles cached in `cache/opentopography/`, mosaic in `cache/cop90_geographic.tif`). Free with attribution (ESA / Airbus / OpenTopography).
- **Processing**: `mapprep/dem.py` `fetch` for the lon/lat frame, then `gdal.Warp` to the custom Albers at 90 m, bilinear, nodata -9999, output bounds = the frame polygon's projected envelope; internal overviews.
- **Rationale**: GLO-90 rather than GLO-30 because at 1:2–3M the 30 m product is 9× the data for no visible gain, and COP90's per-request area limit (4M km²) takes the whole frame in one call. Warped once so the tree-cover raster and all derived layers share one grid and the island labeling is done in equal-area pixels (area_km2 is a pixel count). Cross-border coverage is why Copernicus over 3DEP/PRISM-style US-only data.
- **Facts** *(extracted 2026-08-28)*: Albers Conic Equal Area (lat_0 31, lon_0 -110, parallels 28.3/33.7, WGS84), 29734x28285 px @ 90 m, bounds (-1391319.1449, -1321833.4345, 1284740.8551, 1223816.5655), float32, nodata=-9999.0, overviews [2, 4, 8, 16, 32], deflate, 2097.8 MB

## hillshade_islands.tif, hillshade_islands_z3.tif, hillshade_other_land.tif
- **Role**: Shaded relief split by land class so each class is one layer to style. `hillshade_islands.tif` (z 1.5) and `hillshade_islands_z3.tif` (z 3, more punch at 1:2–3M) cover the 140 filtered sky islands only; `hillshade_other_land.tif` (z 1.5) covers everything else above the shoreline (the `other_land` layer: mainlands + failed candidates ≥ 50 km² — re-masked 2026-09-16 when the scenery floor was added, so the specks are gone from the raster too). The sea is nodata in all three, so it renders flat over `sea_depth.tif`.
- **Source**: `hillshade_multidirectional.tif` (z 1.5) and a z 3 multi-directional hillshade of `dem_cop90_aea.tif` (`cache/hillshade_z3.tif`), masked by the `islands` / `other_land` polygons of `sky-islands.gpkg`.
- **Processing**: `rasterio.features.rasterize` of the polygon set on the DEM grid → hillshade kept inside, nodata 0 outside; deflate, overviews (`write_masked` in `main.py`).
- **Rationale** (2026-08-28): the first layout gave islands and mainlands the same hillshade and the archipelago did not stand out; islands get their own (and a stronger option), everything else can be faded or dropped. Later the same day the mainland / candidate distinction was collapsed into `other_land` because the layout treats them identically and two layers per raster doubled the styling work — this replaced `hillshade_land.tif` (all land in one file, could not be styled per class).
- **Facts** *(extracted 2026-08-28)*: all same Albers grid as the DEM, 29734x28285 px @ 90 m, bounds (-1391319.1449, -1321833.4345, 1284740.8551, 1223816.5655), uint8, nodata=0.0, overviews [2, 4, 8, 16, 32], deflate; islands 3.9 MB, islands_z3 4.0 MB, other_land 164.6 MB

## hillshade_multidirectional.tif
- **Role**: Shaded relief under the island tint (and faintly under the desert basins).
- **Source**: `dem_cop90_aea.tif`.
- **Processing**: `mapprep/hillshade.py` `from_dem`, GDAL multi-directional, z_factor 1.5; overviews.
- **Rationale**: Multi-directional avoids the flat north-facing slopes of a single azimuth on ranges that trend NNW–SSE. z 1.5 is a first guess for a 90 m DEM at this scale; revisit in the layout.
- **Facts** *(extracted 2026-08-28)*: same Albers grid as the DEM, 29734x28285 px @ 90 m, bounds (-1391319.1449, -1321833.4345, 1284740.8551, 1223816.5655), uint8, nodata=0.0, overviews [2, 4, 8, 16, 32], deflate, 407.5 MB

## sea_depth.tif
- **Role**: The desert "sea" — continuous depth surface below the 1,600 m shoreline for a light-to-dark blue ramp in Pro (option B, like the rainfall map's `bathy_srtm15plus.tif`); `elevation_bands` is the stepped option A. Values are metres relative to the shoreline, negative = deeper (0 at the coast, −1,687 in the lowest basin); land is nodata so the ramp stops exactly where the `hillshade_islands` / `hillshade_other_land` rasters start.
- **Source**: `dem_cop90_aea.tif`.
- **Processing**: `elevation − 1600` where the DEM is below the shoreline, −9999 elsewhere (same `high` mask as the islands); float32 deflate, overviews.
- **Rationale** (2026-08-28): replaces the `isobaths` line layer (2026-08-27, removed the next day) — the user preferred the rainfall map's continuous-water look over dashed depth contours. Depth-relative-to-shoreline rather than raw elevation so the symbology reads like the SRTM15+ raster (negative below "sea level") and the ramp can be reused. Symbolize roughly −1,700..0; deepest basins are the lower Gila / Colorado and the Sonoran coast in the west of the frame, far outside the archipelago, so consider clamping the ramp around −800 so the Madrean basins get the full range.
- **Facts** *(extracted 2026-08-28)*: same Albers grid as the DEM, 29734x28285 px @ 90 m, bounds (-1391319.1449, -1321833.4345, 1284740.8551, 1223816.5655), float32, nodata=-9999.0, overviews [2, 4, 8, 16, 32], deflate, 1047.9 MB

## treecover_earthenv_aea.tif
- **Role**: Interim woodland mask — parent of the four `treecover_*` land-clipped tint rasters, and used to attribute each candidate island (`treecover_max`, `treecover_mean`) so treeless high ground can be excluded.
- **Source**: EarthEnv 1 km consensus land cover (Tuanmu & Jetz 2014), tree classes 1–4 summed to percent cover; global class rasters in `$EARTHENV_DIR` (downloaded on first use). Geographic window cached at `cache/treecover_geographic.tif`.
- **Processing**: `mapprep/earthenv.py` `treecover` for the frame, then `gdal.Warp` onto the DEM grid (90 m, bilinear, nodata 255). Values can slightly exceed 100 after resampling (observed max 101).
- **Rationale**: Already on disk and cross-border, so it gets the derivation working end to end. It is coarse (1 km) and "tree" is not "Madrean evergreen woodland" — replace with Brown & Lowe (canonical, coarse polygons) or NALCMS 2020 30 m once downloaded; keep the attribute names so `islands` filtering doesn't change shape.
- **Facts** *(extracted 2026-08-28)*: same Albers grid as the DEM, 29734x28285 px @ 90 m, bounds (-1391319.1449, -1321833.4345, 1284740.8551, 1223816.5655), uint8, nodata=255.0, overviews none, deflate, 105.0 MB

## treecover_islands.tif, treecover_other_land.tif
- **Role**: Woodland tint, one raster per land class — `treecover_earthenv_aea.tif` masked to the `islands` (140 filtered sky islands) and to `other_land` (mainlands + failed candidates ≥ 50 km², re-masked 2026-09-16); the sea is nodata (desert by definition). The islands-vs-other split lets the green wash carry the story: mean cover 56 % on islands vs ~30 % elsewhere.
- **Source**: `treecover_earthenv_aea.tif` + the `islands` / `other_land` layers of `sky-islands.gpkg`.
- **Processing**: rasterize the polygon set on the DEM grid → tree cover kept inside, 255 (nodata) outside; deflate, overviews. Same coarse 1 km EarthEnv values as the parent.
- **Rationale** (2026-08-28): first cut was four options (mainlands / candidates / candidates-not-islands / islands); collapsed to two the same day because the layout styles mainlands and failed candidates identically. Inherits the EarthEnv caveats — swap the parent for Brown & Lowe / NALCMS and these regenerate unchanged.
- **Facts** *(extracted 2026-08-28)*: both same Albers grid as the DEM, 29734x28285 px @ 90 m, bounds (-1391319.1449, -1321833.4345, 1284740.8551, 1223816.5655), uint8, nodata=255.0, overviews [2, 4, 8, 16, 32], deflate; islands 6.3 MB, other_land 61.2 MB

## transect_catalina.csv, transect_catalina.svg
- **Role**: The biome-stack margin panel (brief §3) — one sky island as a vertical cross-section, Tucson (723 m) to the Mount Lemmon summit (2,781 m), 30 km, with the vegetation zones as horizontal strata and the 1,600 m shoreline drawn through the oak-woodland band. The CSV is the profile (distance_km, lon, lat, elev_m, biome, 335 samples at 90 m); the SVG is the finished diagram, editable in Illustrator. **Not placed on the sheet** — decided 2026-09-20 there was no room at a legible size; it accompanies the blog post instead. Palette (2026-09-20): sea blues below the shoreline, island greens sampled from the styled islands above it; latitude-equivalent captions are commented out in `transect.py` and can be restored for the post. The `transect` line in the GeoPackage is the same line for drawing on the map.
- **Source**: `dem_cop90_aea.tif` sampled along the straight line between the two points (`transect.py`, run with `uv run transect.py` after `main.py`).
- **Processing**: line projected to the Albers grid, sampled every 90 m; band breaks 1,200 / 1,500 / 1,950 / 2,200 / 2,500 m (desertscrub → desert grassland → Madrean oak woodland → pine-oak → ponderosa → mixed conifer) from Whittaker & Niering's Santa Catalina gradient (1965), rounded to 50 m and drawn flat; each band carries a latitude-equivalent caption for the "Mexico to Canada in an hour" line. Vertical exaggeration 7×.
- **Rationale** (2026-09-19): the Catalinas because Tucson is on the map and the Mount Lemmon highway is the canonical example; a straight line rather than the road so the profile is honest DEM, not a switchback. Band elevations come from the literature, not the 1 km EarthEnv tree cover, which is too coarse to resolve zones. The shoreline crosses the profile at 17.6 km, 1.4 km after oak woodland is first reached — i.e. the 1,600 m definition sits inside the woodland band, which is what the panel is there to show.
- **Facts**: CSV 335 rows; SVG 720×360 px, Georgia serif, greens matching the islands (`#c5cc9a`–`#748d58`), sea wash `#8fb8d0` at 35 %.

## sky-islands.gpkg

### islands
- **Role**: The map — each feature is one sky island at the 1,600 m shoreline, filtered to plausible ranges.
- **Source**: `dem_cop90_aea.tif` + `treecover_earthenv_aea.tif`.
- **Processing**: `elevation >= 1600` → `scipy.ndimage.label` with 8-connectivity → drop components touching the edge of valid data (→ `other_land`, kind = mainland) → per-component stats via `ndimage.sum_labels/maximum/mean` → `rasterio.features.shapes` dissolved by `island_id` → keep `madrean` (representative point inside the archipelago box 113–107°W / 27–35°N — the brief's region padded a degree), `area_km2 >= 5`, and `treecover_max >= 15`. Fields: `island_id` (label number, stable only within a run), `area_km2` (equal-area pixel count × 0.0081), `elev_max_m`, `prominence_m` (= elev_max − 1600, height above the sea), `treecover_max`, `treecover_mean` (EarthEnv %), `name` + `tier` + `confidence` (2026-09-19: 39 of 143 named; `tier` 1 = eight marquee ranges, 2 = next twelve, 3 = the rest — label `tier <= 1` or `<= 2`, never all 39, which crammed together on the first try; from `names.csv`, the literature's range list as one point per range, matched to the nearest island within 5 km; `confidence` high = Wikipedia/OSM coordinates, medium/low = Sonoran sierras placed from towns and landmarks because neither Wikipedia nor OSM geocodes them — eyeball the low ones: Cucurpe, Huachinera, La Púrica). Derived on the Albers grid, reprojected to EPSG:4326 on write (`area_km2` is from the equal-area pixels, not the 4326 geometry). Sorted by area descending. Unsmoothed: the pixel-edge shoreline is the honest derivation; generalize in Pro or via `elevation_bands` if needed.
- **Rationale**: 1,600 m is Deyo's definitional elevation, cited in the brief. 8-connectivity so a saddle at exactly threshold keeps two ridges as one island (errs toward merging, which matches how ranges are named). Mainland = touches the *valid-data* edge, not the array edge — the lon/lat frame warps to a curved quadrilateral in Albers so array corners are nodata; the first run used array edges and the whole Sierra Madre (54,000 km²) survived as an "island". The 5 km² / 15 % cutoffs are deliberately loose first guesses (140 Madrean islands vs the literature's ~55 — many are foothill spurs and mesas); tune against `islands_candidates` once the woodland mask is the real one. *(2026-08-28)* 143 islands on the enlarged frame vs 140 before: the new warp grid shifts pixel alignment, so three borderline landmasses crossed the 5 km² / edge tests — the island set is grid-sensitive at the margins, another reason the cutoffs are provisional. Spot-check 2026-08-20: largest islands are the Chiricahuas (1,255 km², 2,973 m), the Huachucas, and the Pinaleños (3,253 m) — the derivation finds the right things. *(2026-09-19 naming pass)*: every major US range in the Wikipedia list lands on its own island with no collisions; the misses are diagnostic. The Peloncillo / Animas / Sierra San Luis / Pan Duro chain and the Cookes Range sit **on a mainland** — the continental-divide ridge fuses them to the Sierra Madre block (and the Gila to the Rim) at 1,600 m, which is the shoreline caveat already noted, now with names for the margin note. The Superstitions, Tumacácoris and Pyramids fall below the shoreline (no polygon), and Sierra Mazatán / Elenita did not resolve to a distinct island. Label class in Pro: `name IS NOT NULL`, italic serif, placed in the sea beside the island (Maplex offset), priority by `area_km2`.
- **Facts** *(extracted 2026-09-19)*: EPSG:4326, MultiPolygon, 143 features (39 named), fields [island_id, area_km2, elev_max_m, prominence_m, treecover_max, treecover_mean, madrean, name, tier, confidence]

### islands_candidates
- **Role**: Every non-mainland component at 1,600 m, unfiltered — for tuning the area and woodland cutoffs in Pro with definition queries. Carries a `madrean` flag: representative point inside the archipelago box (113–107°W / 27–35°N). The display frame is much larger than the region, so the frame must not define membership — western-Arizona / Baja / deep-Chihuahua high ground is scenery, not sky islands (2026-08-27); the naming pass against the ~55-range list will supersede the box.
- **Source / Processing**: as `islands`, before the area/tree-cover filter. Same fields.
- **Rationale**: The filter thresholds are the least settled part of the derivation; keeping the full set means re-tuning doesn't need a rerun. Mostly slivers (12,357 features, most under 1 km²).
- **Facts** *(extracted 2026-08-28)*: EPSG:4326, MultiPolygon, 16085 features, fields [island_id, area_km2, elev_max_m, prominence_m, treecover_max, treecover_mean, name, madrean]

### other_land
- **Role**: All land that is not a sky island, as one layer — the two continental "coasts" (Colorado Plateau / Mogollon Rim, Sierra Madre Occidental) plus every candidate that failed the area / woodland / Madrean-box filter **and is at least `min_display_km2` = 50 km²** (foothill spurs, mesas, out-of-region ranges — the pixel specks are gone). The layout styles these identically (flat, receding), so they ship as one layer; `kind` (`mainland` / `candidate`) keeps the distinction queryable, and mainland `name` is set by latitude as before (northernmost edge-touching block → Plateau, southernmost → Sierra Madre, fragments null).
- **Source / Processing**: the mainlands (the ≥ 1,600 m components touching the edge of valid data) concatenated with `islands_candidates` minus `islands`, the latter filtered to `area_km2 >= min_display_km2` (50). Same fields as `islands` plus `kind`.
- **Rationale** (2026-08-28): replaces the separate `mainlands` layer — two land layers (islands / everything else) instead of three halved the styling work in Pro. The mainland test is unchanged: connected to something that leaves the frame. Consequence still worth a margin note: the Gila / Black Range block fuses with the Rim at this threshold, so SW New Mexico's ranges are `other_land`, not islands. *(2026-09-16)* Scenery floor added after the first full layout: the 15,942 failed candidates were ~15,700 sub-50 km² specks across Chihuahua, Nevada and California — the busiest thing on the page, out-shouting islands that are smaller and quieter than many of them. At 50 km² the layer keeps 207 candidates holding 86 % of the failed-candidate area, and nothing kept is smaller than a typical island (islands: min 5, median 25, max 1,255 km²); 20 km² would keep 337, 100 km² 140. Chosen over a Pro definition query because `hillshade_other_land` / `treecover_other_land` are masked by this layer, so a display-only filter would have left the specks in the rasters. `islands_candidates` still carries every fragment. Applied to the existing outputs with a targeted rewrite (same code path as `main.py`), not a full rerun.
- **Facts** *(extracted 2026-09-16)*: EPSG:4326, MultiPolygon, 246 features (39 mainland-kind incl. edge fragments, 207 candidates ≥ 50 km²), fields [island_id, area_km2, elev_max_m, prominence_m, treecover_max, treecover_mean, name, kind]

### border
- **Role**: The US–Mexico border as one line, so it can be styled apart from the state boundaries (the brief wants it present but not dominant; on the 2026-09-19 layout it was indistinguishable from the state dashes, and half the islands are in Mexico).
- **Source / Processing**: derived from `states` — dissolve the US and Mexican states separately, intersect the two boundaries, keep the line parts, dissolve. Field `name`. EPSG:4326.
- **Rationale**: Natural Earth's own `admin_0_boundary_lines_land` is only on disk at 50m while `states` is 10m, and a 50m border would not sit on the 10m state edges; deriving it from the same polygons guarantees coincidence.
- **Facts** *(extracted 2026-09-19)*: EPSG:4326, MultiLineString, 1 feature, fields [name]

- **Source / Processing**: `transect.py`; straight line between downtown Tucson (-110.9747, 32.2226) and the summit (-110.7883, 32.4433). Fields `name`, `length_km`.
- **Facts** *(extracted 2026-09-19)*: EPSG:4326, LineString, 1 feature, fields [name, length_km]

### elevation_bands
- **Role**: Hypsometric tint / reverse bathymetry — bands below the shoreline deepen the desert basins, bands above tint the islands. Also the honest display of shoreline sensitivity (1,200 / 1,400 m show which islands would merge if the sea dropped).
- **Source**: `dem_cop90_aea.tif`.
- **Processing**: `mapprep/raster.py` `classify_to_polygons` with breaks `[1200, 1400, 1600, 1800, 2100, 2400, 2700, 3000]`, `smooth_sigma=2`, `upsample=2`, `sieve_pixels=200`, `simplify_tolerance=60` m. Fields `class`, `lower`, `upper`, `label`.
- **Rationale**: Smoothed and sieved so the bands read as chart fills at 1:2–3M; because of the smoothing the 1,600 m edge here will not coincide exactly with the unsmoothed `islands` shoreline — draw `islands` on top. Breaks widen with elevation (200 → 300 m) since area falls off fast above 2,400 m.
- **Facts** *(extracted 2026-08-28)*: EPSG:4326, MultiPolygon, 9 features, fields [class, lower, upper, label]

### contours
- **Role**: Topographic contour lines on the land (islands and mainlands) above the shoreline, drawn over the masked hillshade; `index` marks the 1,000 m multiples (2,000 / 3,000 m) for a heavier stroke.
- **Source**: `dem_cop90_aea.tif`.
- **Processing**: one `gdal.ContourGenerate` pass on the full DEM at fixed levels — 1,800 m to the DEM maximum every 200 m; simplified 60 m; closed loops shorter than 2 km dropped (single-pixel specks). Fields `elev_m`, `index`. No clipping needed: any level above 1,600 m lies inside the ≥ 1,600 m mask by construction.
- **Rationale** (2026-08-27): 200 m is a first guess for 90 m data at 1:2–3M — dense on the steep ranges, so lean on the hillshade and consider thinning to 300 m or drawing only index contours in the layout. The 1,600 m line itself is deliberately absent: that is the shoreline, drawn from `islands` / `other_land`.
- **Facts** *(extracted 2026-08-28)*: EPSG:4326, LineString, 25905 features, fields [elev_m, index]

### physiographic_provinces, physiographic_sections
- **Role**: Reference only (not for display) — Fenneman physiographic provinces and their sections, for placing the two mainland labels: **Colorado Plateaus** is the province (label it over Flagstaff–Holbrook), the Mogollon Rim is its southern boundary (label along the line where Colorado Plateaus meets Basin and Range / Mexican Highland), and the Transition Zone below the Rim is what actually forms the northern mainland's coast at 1,600 m. Also shows the Mexican Highland and Sonoran Desert sections the islands sit in.
- **Source**: USGS *Physiographic divisions of the conterminous U.S.* (Fenneman & Johnson 1946), `https://water.usgs.gov/GIS/dsdl/physio_shp.zip`, downloaded on first run to `cache/physio/`. Public domain. **CONUS only** — Mexico has no coverage; the Sierra Madre Occidental label has to go by eye (or by the `other_land` polygon).
- **Processing**: columns `division`, `province`, `section` (title-cased), EPSG:4326, clipped to the frame, dissolved to one feature per section (26) and per province (11).
- **Rationale** (2026-08-28): added when the user asked where the Colorado Plateau and Mogollon Rim start and end. Dissolved because the source splits each section into many polygons.
- **Facts** *(extracted 2026-08-28)*: provinces — EPSG:4326, MultiPolygon, 11 features, fields [division, province]; sections — EPSG:4326, MultiPolygon, 26 features, fields [division, province, section]

### frame
- **Role**: The lon/lat map frame as a polygon (segmentized every 0.1° so it curves correctly when projected); the extent rectangle on the locator inset, and a clip/extent reference in Pro.
- **Facts** *(extracted 2026-08-28)*: EPSG:4326, Polygon, 1 features, fields []

### states
- **Role**: US and Mexican state linework, clipped to the frame (which already carries margin beyond the layout). *(2026-08-28: briefly shipped unclipped — 4,596 features — together with the global 10m ocean; Pro rendering bogged down, so both are clipped again.)*
- **Source**: Natural Earth 10m admin-1 states/provinces (`$NATURAL_EARTH_DIR/StatesProvinces/ne_10m_admin_1_states_provinces/`), read directly — `mapprep.natural_earth.states_provinces` uses the 50m `_lakes` file, which carries first-order subunits for only a handful of countries and has no Mexican states.
- **Processing**: columns trimmed to `name`, `admin`, `iso_3166_2`; geopandas clip to the frame.
- **Facts** *(extracted 2026-08-28)*: EPSG:4326, MultiPolygon, 36 features, fields [name, admin, iso_3166_2]

### ocean
- **Role**: The real ocean — Gulf of California and the Pacific in the SW of the frame — so actual water can be styled distinctly from the desert "sea" (`sea_depth.tif`) and the metaphor doesn't collide with it. Draw above `sea_depth.tif`.
- **Source**: Natural Earth **10m** ocean via `mapprep.natural_earth.ocean(scale='10m')`, clipped to the frame — the unclipped 10m ocean is one global polygon and bogged Pro's rendering. *(2026-08-28: first written from the 50m file — its coastline visibly disagreed with the 10m `states` in the Gulf of California; the two must share a scale.)*
- **Rationale** (2026-08-28): added when `countries`, `border` and `shoreline_vignette` were dropped as unused in the layout (states already carry the US–MX line; the vignette didn't earn its place once the islands got their own hillshade).
- **Facts** *(extracted 2026-08-28)*: EPSG:4326, MultiPolygon, 1 features, fields [featurecla, scalerank, min_zoom]

### cities
- **Role**: The six cities that go on the map, styled as harbour marks on the chart — orientation, not data: Tucson (the essential one — a million people on the "seafloor" beside the Catalinas), Phoenix, El Paso (labelled *El Paso / Ciudad Juárez*), Hermosillo, Chihuahua, Albuquerque. Draw as small open circles, Kumbh Sans, no size classes. `label` is the display text.
- **Source / Processing**: `populated_places` filtered by name; Juárez is not in the source at this scalerank so El Paso carries both names.
- **Rationale** (2026-08-28): hand-picked rather than a scalerank cutoff — the full 42-point set scatters dots across the sea and breaks the metaphor. Albuquerque included provisionally; drop it if it falls awkwardly near the frame.
- **Facts** *(extracted 2026-08-28)*: EPSG:4326, Point, 6 features, fields [name, label, adm0name, pop_max]

### populated_places
- **Role**: Reference cities (Tucson, Hermosillo, Chihuahua, …) for orientation labels.
- **Source**: Natural Earth 50m populated places, bbox-filtered to the frame; fields `name`, `adm0name`, `scalerank`, `pop_max`.
- **Facts** *(extracted 2026-08-28)*: EPSG:4326, Point, 42 features, fields [name, adm0name, scalerank, pop_max]
